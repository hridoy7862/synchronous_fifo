# Synchronous FIFO

## 1. Project Overview

This project implements a **Synchronous FIFO (First-In-First-Out)** for temporary data storage and sequential data transfer between a source/sender logic and a destination/receiver logic.

Unlike an asynchronous FIFO, both read and write operations are controlled by the **same clock domain**.

The design uses:

- Single clock
- Memory for data storage
- Write pointer (`wptr`)
- Read pointer (`rptr`)
- FIFO full detection
- FIFO empty detection
- Write enable (`wen`)
- Read enable (`ren`)
- Reset control

The main goal is to store incoming data in FIFO order and provide the stored data to the receiver in the same order.

The FIFO consists of a memory block, write pointer and full-control logic, and read pointer and empty-control logic.

### Source/Sender Logic

The source logic provides:

- `wdata`
- `wen`

The source can write data into the FIFO only when the FIFO is not full.

The `full` signal is generated by the write pointer and full-control logic and is sent back to the source logic.

### FIFO Memory

The memory stores the incoming data.

A write operation uses the current write pointer:

`memory[wptr] = wdata`

A read operation provides data from the current read pointer:

`rdata = memory[rptr]`

Since the FIFO is synchronous, both operations are controlled by the same clock.

### Destination/Receiver Logic

The destination logic provides:

- `ren`

The receiver can read data from the FIFO only when the FIFO is not empty.

The `empty` signal is generated by the read pointer and empty-control logic and is sent to the receiver.

## 3. Methodology

### Write Operation

A write occurs on the rising edge of `Clock` when:

`wen = 1`

and:

`full = 0`

The write process is:

`wen && !full` → Write data to memory → Increment `wptr`

The data is stored at the location indicated by the current write pointer.

After a successful write, the write pointer moves to the next memory location.

### Read Operation

A read occurs on the rising edge of `Clock` when:

`ren = 1`

and:

`empty = 0`

The read process is:

`ren && !empty` → Read data from memory → Increment `rptr`

The data at the location indicated by the current read pointer is provided as `rdata`.

After a successful read, the read pointer moves to the next memory location.

## 4. FIFO Full and Empty Logic

### Full Detection

The FIFO is full when the write pointer reaches the condition corresponding to the maximum available storage.

When the FIFO is full:

`full = 1`

The write operation is disabled to prevent overwriting existing data.

Therefore:

`wen && !full`

must be true for a valid write.

### Empty Detection

The FIFO is empty when the read pointer indicates that there is no unread data available.

When the FIFO is empty:

`empty = 1`

The read operation is disabled to prevent reading invalid data.

Therefore:

`ren && !empty`

must be true for a valid read.

## 5. FIFO Operation

The FIFO follows the First-In-First-Out principle.

For example, if the following data is written:

`D1 → D2 → D3 → D4`

the data will be read in the same order:

`D1 → D2 → D3 → D4`

The write pointer controls where new data is stored, while the read pointer controls where the next data is retrieved.

## 6. Reset Operation

The reset initializes the FIFO to an empty state.

After reset:

- `wptr` is initialized
- `rptr` is initialized
- `empty` is asserted
- `full` is deasserted

This ensures that the FIFO starts from a known state before normal operation begins.

## 7. Verification Testcases

The FIFO is verified using different functional scenarios to check normal operation and boundary conditions.

| Testcase | Purpose |
|----------|---------|
| Reset Test | Verify correct initialization of pointers and status signals |
| Single Write/Read | Verify one complete write and read operation |
| Multiple Write/Read | Verify sequential data storage and retrieval |
| Write Until Full | Verify correct `full` generation |
| Read Until Empty | Verify correct `empty` generation |
| Full Protection | Verify that writing is prevented when the FIFO is full |
| Empty Protection | Verify that reading is prevented when the FIFO is empty |
| Simultaneous Read/Write | Verify read and write operations in the same clock cycle |
| Pointer Wrap-Around | Verify correct operation when pointers return to the beginning of memory |
| Sequential Data Integrity | Verify that data is read in exactly the same order in which it was written |

### Main Verification Objective

The main verification goal is to ensure that:

`Data written into FIFO = Data read from FIFO`

while also verifying:

- Correct `full` generation
- Correct `empty` generation
- Correct write pointer operation
- Correct read pointer operation
- FIFO ordering
- Overflow protection
- Underflow protection
- Pointer wrap-around
- Correct simultaneous read/write behavior

## 8. Key Features

- Synchronous FIFO design

- FIFO full detection

## 10. Summary

This project demonstrates the design and verification of a **Synchronous FIFO** for reliable sequential data storage and transfer within a single clock domain.

The design combines memory, write pointer and full-control logic, read pointer and empty-control logic, and source/destination interfaces to provide ordered and controlled data transfer between the sender and receiver.
